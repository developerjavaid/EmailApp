Prerequisites

Everything in this runbook assumes a Linux host (this project was run on Ubuntu 22.04) with the following already reachable:

  • An Azure subscription with rights to create resources in resource group devteam-projectnour-rg.
  • A Databricks workspace on Azure (adb-7405605860283973.13.azuredatabricks.net) with Unity Catalog enabled.
  • A Microsoft Entra app registration used as the shared service principal for both Databricks and email — client ID d97d0f55-a968-43a0-94c6-5d433ac05874, tenant af332e32-a9ba-4ca0-b37a-2b07a41c8f59.
  • Python 3.10, Node.js/npm (for tooling, not runtime), and root/sudo access for package installs.
02

Key Vault & Secrets

One secret carries the entire app: the Entra application's client secret, read by both the Databricks connection and the email send path. It lives in Key Vault as aad-client-secret-value, fetched through config.py's get_secret() via DefaultAzureCredential — your CLI login locally, the Function App's managed identity in Azure.

⚠️
Gotcha

Entra ID shows two columns when you create a client secret: Secret ID (a GUID, just an identifier) and Value (the actual credential). Copying the ID instead of the Value produces a vault secret that looks valid but fails token requests with AADSTS7000215. The Value is shown once, at creation — it cannot be retrieved afterward.

bash
# provision the vault, store the secret, wire up both identities
az keyvault create --name email-vault --resource-group devteam-projectnour-rg \
  --location centralus --enable-rbac-authorization true

az keyvault secret set --vault-name email-vault \
  --name aad-client-secret-value --value "<paste the Secret VALUE, not the Secret ID>"

# your own login, for local dev
az role assignment create --role "Key Vault Secrets User" \
  --assignee jvm@analyticsintellect.com --scope $(az keyvault show --name email-vault --query id -o tsv)

# the Function App's managed identity, for the deployed app
PRINCIPAL_ID=$(az functionapp identity assign --name ViaSmiles-EmailApp \
  --resource-group devteam-projectnour-rg --query principalId -o tsv)
az role assignment create --role "Key Vault Secrets User" \
  --assignee $PRINCIPAL_ID --scope $(az keyvault show --name email-vault --query id -o tsv)
03

Local Environment

Standard Python Functions setup, plus two tooling installs that don't behave the way their default instructions suggest on a headless Linux box running as root.

Python dependencies

bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

Sign in without a browser

A headless root shell can't launch a sandboxed Chromium for the normal az login flow. Use the device-code flow instead — it authenticates from any browser, anywhere:

bash
az login --use-device-code

Install Azure Functions Core Tools via apt, not npm

The npm package's install script pulls a newer https-proxy-agent that ships ESM-only — Node 18's CommonJS installer can't require() it, and the install fails with ERR_REQUIRE_ESM. Microsoft's apt package sidesteps it entirely:

bash
curl -sSL https://packages.microsoft.com/config/ubuntu/22.04/packages-microsoft-prod.deb -o packages-microsoft-prod.deb
sudo dpkg -i packages-microsoft-prod.deb && rm packages-microsoft-prod.deb
sudo apt-get update && sudo apt-get install azure-functions-core-tools-4

Databricks Access

The service principal needs four separate, independent grants before a single row is readable. Missing any one of them fails at a different layer, which is what makes this stage worth doing in order.

1 — Create the schema and table

sql
CREATE SCHEMA IF NOT EXISTS claraport_ws.prd_viasmiles_email;

CREATE TABLE IF NOT EXISTS claraport_ws.prd_viasmiles_email.customer (
  fname STRING,
  email STRING
);

2 — Add the service principal to the workspace

Workspace → user menu → Admin Settings → Identity and access → Service principals → add client ID d97d0f55-a968-43a0-94c6-5d433ac05874. On a Unity-Catalog / account-managed workspace, this may need to happen in the separate Account Console first, then get assigned to the workspace.

3 — Grant "Can Use" on the SQL Warehouse

This is compute access, and it's entirely separate from data access — SQL Warehouses → the warehouse behind /sql/1.0/warehouses/3fd364899555d7d7 → Permissions tab → add the service principal → Can Use.

4 — Grant Unity Catalog data access

sql
GRANT USE CATALOG ON CATALOG claraport_ws TO `d97d0f55-a968-43a0-94c6-5d433ac05874`;
GRANT USE SCHEMA ON SCHEMA claraport_ws.prd_viasmiles_email TO `d97d0f55-a968-43a0-94c6-5d433ac05874`;
GRANT SELECT, MODIFY ON TABLE claraport_ws.prd_viasmiles_email.customer TO `d97d0f55-a968-43a0-94c6-5d433ac05874`;

Seed a test row

sql
INSERT INTO claraport_ws.prd_viasmiles_email.customer (fname, email) VALUES
  ('javaid', 'developer.javaid@gmail.com'),
  ('javaid', 'jvm@analyticsintellect.com'),
  ('javaid', 'developer.javaid4@gmail.com');
05

Service Principal Auth

The connector library defines a fixed set of auth_type values internally. Anything outside that set fails silently — no validation error, it just falls through to the connector's default flow, which happens to be interactive browser OAuth.

⚠️
Gotcha

A plausible-looking value like "azure-client-secret" isn't recognized by databricks-sql-connector v4.4.0 — the correct enum value is "azure-sp-m2m". Get it wrong and the function doesn't error, it hangs indefinitely waiting for a browser callback at localhost:8020 that a headless server will never receive.

db_utils.py
# before — silently wrong, falls back to interactive OAuth
auth_type="azure-client-secret",

# after — matches AuthType.AZURE_SP_M2M in the installed connector
auth_type="azure-sp-m2m",
06

ACS Email Delivery

This stage took the most iterations, because SMTP AUTH for Azure Communication Services doesn't work the way OAuth SMTP normally does elsewhere. Three independent things have to be correct simultaneously, and a 535 5.7.3 Authentication unsuccessful response looks identical regardless of which one is wrong.

The role: Communication and Email Service Owner

Not Contributor — Microsoft's own docs specify a dedicated built-in role for this feature. Communication Services resource → Access control (IAM) → assign Communication and Email Service Owner to the service principal.

The SMTP username: its own linked resource

Distinct from the MailFrom address, and created under the Communication Services resource's own SMTP Usernames blade — linked explicitly to the Entra application. In this project it's ViaSmile-Smtp.

The password: the raw client secret — not an OAuth token

⚠️
Root cause

The original code acquired an MSAL access token (scope=https://communication.azure.com/.default) and sent that as the SMTP password. Per Microsoft's documented protocol, ACS does the Entra token exchange on its own backend, using the app linked to the SMTP username — the client is only ever expected to send the client secret itself. Every fix to role, username, or sender address failed to resolve the 535 until this was corrected.

email_utils.py — before
app = msal.ConfidentialClientApplication(client_id, client_secret, authority)
result = app.acquire_token_for_client(scopes=["https://communication.azure.com/.default"])
server.login(smtp_username, result["access_token"])  # wrong — 535 every time
email_utils.py — after
client_secret = get_secret("aad-client-secret-value")
server.login(smtp_username, client_secret)  # correct — ACS exchanges it server-side

With the MSAL flow gone, msal also came out of requirements.txt — it's no longer used anywhere in the app.

Local Testing

The function ignores its own AuthLevel.FUNCTION setting when run through Core Tools locally — no function key needed until it's deployed.

bash
func start
# in a second terminal
curl -X POST "http://localhost:7071/api/send-customer-emails"

Expect a plaintext summary: Sent: 3, Failed: 0. Failed addresses: []. Watch the func start terminal in parallel — failures are logged there with a full traceback, never raised back through the HTTP response.

Deploy to Azure

local.settings.json is gitignored and never uploaded by func publish — every value in it has to be pushed to the Function App separately.

bash
az functionapp config appsettings set \
  --name ViaSmiles-EmailApp --resource-group devteam-projectnour-rg \
  --settings \
    AAD_TENANT_ID="af332e32-a9ba-4ca0-b37a-2b07a41c8f59" \
    AAD_CLIENT_ID="d97d0f55-a968-43a0-94c6-5d433ac05874" \
    DATABRICKS_SERVER_HOSTNAME="adb-7405605860283973.13.azuredatabricks.net" \
    DATABRICKS_HTTP_PATH="/sql/1.0/warehouses/3fd364899555d7d7" \
    DATABRICKS_CATALOG="claraport_ws" DATABRICKS_SCHEMA="prd_viasmiles_email" \
    DATABRICKS_TABLE="customer" DATABRICKS_AUTH_TYPE="service_principal" \
    ACS_SMTP_HOST="smtp.azurecomm.net" ACS_SMTP_PORT="587" \
    ACS_SMTP_USERNAME="ViaSmile-Smtp" \
    ACS_SENDER_ADDRESS="DoNotReply@fd88cc4b-c805-4515-919a-74382085ed51.azurecomm.net"
⚠️
Gotcha

func azure functionapp publish refuses to run if the target app has no AzureWebJobsStorage setting — it needs a real storage account connection string, not the UseDevelopmentStorage=true emulator value used locally.

bash
STORAGE_CONN=$(az storage account show-connection-string --name claraportstorage \
  --resource-group devteam-projectnour-rg --query connectionString -o tsv)

az functionapp config appsettings set --name ViaSmiles-EmailApp \
  --resource-group devteam-projectnour-rg --settings AzureWebJobsStorage="$STORAGE_CONN"

func azure functionapp publish ViaSmiles-EmailApp

Viewing the deployed source

The Portal's SSH console is unreliable on a Consumption plan — if keystrokes don't register, skip straight to the Kudu file browser instead: https://viasmiles-emailapp.scm.azurewebsites.net → file tree → site/wwwroot. Click any file to view it, no terminal required.

09

Monitor & Verify

Metrics on the Communication Services resource give aggregate counts only. Per-recipient delivery outcome — sent, bounced, suppressed — needs Diagnostic settings pointed at a Log Analytics workspace.

Wire it up

Communication Services resource → Diagnostic settings → add a setting sending EmailSendMailOperational and EmailStatusUpdateOperational to a Log Analytics workspace.

Query delivery status

kql
ACSEmailStatusUpdateOperational
| where TimeGenerated > ago(1h)
| project TimeGenerated, MessageId, Sender, Recipient, Status, StatusDetail
| order by TimeGenerated desc

Status resolves to Delivered, Bounced, Failed, Suppressed, or Quarantined per message. At this app's current send volume, ingestion stays far under the 5 GB/day free allowance — cost is effectively nil unless volume grows into the thousands-per-day range.
